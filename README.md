# 医院挂号系统

## 一、需求分析

### 功能性需求
1. 实现线上预约挂号，自动生成预约序号与推荐就诊时间
2. 实现线下现场挂号，区分普通挂号与复诊挂号
3. 支持线上预约患者签到，签到后进入排队序列
4. 完成多队列合并，实现复诊患者优先排队规则
5. 对合并队列进行排序，保证排队顺序有序
6. 按照就诊科室自动分流患者，存入对应科室链表
7. 限制每个科室每日最大挂号号源，号源满提示禁止挂号
8. 实时查看全院整体排队信息与各科室排队人数、叫号状态
9. 实现医生端一键叫号，自动完成患者出队
10. 程序退出时释放所有动态内存，避免内存泄漏

### 非功能性需求
1. 操作界面简洁，中文提示清晰，容错性强
2. 代码结构分层明确，模块化编写，易于阅读修改
3. 运行稳定，队列边界、空队列、满队列情况处理完善
4. 逻辑贴合真实医院就诊流程，实用性强

### 2.3 队列整体架构
1. **数组队列**：线上预约信息存储
2. **循环队列**：线下排队队列、签到队列、复诊优先队列

4. **单链表队列**：每个科室独立患者排队链表

## 三、核心算法设计
### 3.1 多队列优先级合并算法
1. 合并优先级顺序：**复诊队列 > 线下普通队列 > 线上签到队列**
2. 依次遍历取出三个队列数据，存入总合并队列
3. 保证复诊患者优先获得就诊权限，符合医院实际规则

### 3.2 大顶堆排序算法
1. 将合并完成的无序队列构建大顶堆
2. 不断交换堆顶与末尾元素并调整堆结构
3. 最终实现排队序号从小到大升序排列，规范就诊顺序

### 3.3 科室匹配查找算法
利用`strcmp`字符串比对，遍历科室名称数组，精准匹配用户输入科室，完成科室合法性校验与下标定位。

### 3.4 单链表基础操作算法
1. 尾插法：将患者信息插入对应科室链表尾部
2. 头删法：叫号时删除链表头部第一位就诊患者
3. 链表遍历：统计科室排队人数、展示排队信息
4. 链表销毁：批量释放链表所有节点动态内存

### 3.5 循环队列操作算法
通过队头、队尾下标取模运算，实现循环队列入队、出队、遍历，有效利用数组空间。

## 四、业务流程设计
### 4.1 系统整体流程
1. 程序启动，完成所有队列、科室结构体全部初始化
2. 加载测试数据，方便功能调试
3. 进入主功能选择菜单
4. 用户选择对应功能完成挂号、签到、查询、叫号操作
5. 完成队列合并、排序、科室分流
6. 医护人员执行叫号操作，患者依次就诊
7. 选择退出系统，统一释放全部内存，程序结束

### 4.2 线上预约业务流程
输入姓名 → 选择就诊科室 → 系统校验科室合法性 → 分配预约序号 → 自动生成推荐就诊时间 → 保存预约信息 → 预约成功

### 4.3 预约签到业务流程
输入预约序号 → 校验序号是否存在 → 判断是否重复签到 → 签到成功 → 加入签到排队队列

### 4.4 线下挂号业务流程
输入姓名与科室 → 选择是否复诊 → 普通患者进入线下队列 → 复诊患者进入优先队列 → 挂号成功

### 4.5 排队分流与叫号流程
触发队列合并 → 按优先级整合队列 → 堆排序规整顺序 → 批量分配至对应科室链表 → 查看科室排队状态 → 医生叫号 → 头部患者出队就诊

## 五、难点与解决方法

### 5.1 难点一：线上预约患者签到顺序问题
**问题**：线上预约患者的取号顺序和签到顺序是不确定的
**解决办法**：线上预约的患者采用数组储存，签到只需要查找对应下标的数组有无数据，将签到后的患者直接由队列储存，在合并后再在合并后的队列中进行堆排序
### 5.1 难点二：多队列优先级整合混乱
**问题**：复诊、线下、线上三类患者队列混杂，无法区分就诊优先级。
**解决方法**：严格设定合并先后顺序，优先存入复诊患者数据，再存入线下、线上患者，从源头确定就诊优先级。

### 5.2 难点三：排队顺序杂乱无序
**问题**：多队列合并后序号错乱，无法按照取号先后就诊。
**解决方法**：引入大顶堆排序算法，对合并后整体队列进行排序，统一规整排队次序。

### 5.3 难点四：科室号源超额问题
**问题**：无人数限制导致同一科室挂号人数过多，超出接诊能力。
**解决方法**：在科室结构体中设置人数统计变量，患者入科前进行判断，达到每日上限直接提示号源已满。

### 5.4 难点五：动态内存造成内存泄漏
**问题**：大量使用`strdup`动态开辟字符串内存，程序结束容易遗漏释放。
**解决方法**：叫号时实时释放当前就诊患者内存，系统退出时遍历所有科室链表，逐层释放节点、字符串、科室结构体内存。

### 5.5 难点六：循环队列边界处理易错
**问题**：队头队尾指针移动容易出现数组越界、队列判空判满错误。
**解决方法**：所有循环队列统一使用取模方式更新下标，固定队列操作格式，统一逻辑避免出错。

### 5.6 难点七：科室输入错误无法拦截
**问题**：用户输入不存在科室名称，程序直接崩溃或异常存入。
**解决方法**：增设科室查询校验函数，输入错误提示重新选择，同时支持查看全部科室列表辅助选择。

### 5.7 难点八：队列数据处理
**问题**:合并后的队列在进入诊室后会全部清除，这时再有新的数据会排在已经进入诊室的数据后面，复诊患者的优先级就会降低
**解决办法**：在诊室添加患者的函数内增加一个计数器，函数每次运行每次每个诊室只添加一个患者，避免一次性直接将总队列清空
